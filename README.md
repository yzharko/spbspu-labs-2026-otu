Лабораторные работы
===================

Правила
-------

* Каждый студент размещает свои работы в каталоге со своим именем на
  английском языке, строчными буквами и разделив фамилию и имя
  точкой, например, `lastname.firstname`.

* Код / скрипты / схемы размещаются в отдельной директории `src`. 
  При этом, каждая работа должна находится в каталоге, имя которого
  представляет собой объединение заглавной латинской буквы,
  обозначающей читаемый курс ("L" для ОТУ) и
  номера работы, например, `lastname.firstname/src/L1` для первой работы по ОТУ.

* Каждый отчёт размещается в отдельной директории `materials`.
  Все отчёты должны быть представлены в формате PDF. Отдельные директории 
  для каждого отчёта делать **не нужно**  

* Каждая работа должна быть выполнена в отдельном Pull
  Request-е. Соответственно, не допускаются следующие ситуации:

    - более одной работы внутри Pull Request-а, но, если работа
      требует исправления уже сданных работ, такие изменения *должны*
      быть выполнены в том же Pull Request-е, так как поддерживают
      корректность проекта;

    - несколько Pull Request-ов для одной и той же работы, за
      исключением предыдущего пункта, так как каждый Pull Request
      обеспечивает отслеживание истории изменений и приема работы.

* Изменения в Pull Request должны быть выполнены относительно самого
  свежего коммита в ветке "master" основного проекта. Достигается это
  операциями "merge" и "rebase" (см. документацию по
  [Git](https://git-scm.com/book)).

### Compliance Guide (CG)
- Ветка `master` является основной.
- **push** на ветку  `master` **запрещен**.
- Лабораторные работы (далее ЛР) реализуются в ветке, с названием по типу
  `lastname.firstname/L{номер-ЛР}`, которая отводится от ветки `master`
- Наименования коммитов:
  `OTU-L{номер-ЛР}: {краткое-описание-новой-версии}`
- Наименование Pull Request-а (далее PR-а):
  `lastname.firstname/L{номер-ЛР}`
- Фигурные скобки `{}` в названии ставить **не нужно**, они нужны для наглядности шаблона названия ветки.  
  **Пример именования ветки**: `zharko.yegor/L1`
  **Пример именования коммита**: `OTU-L1: Добавлено очень много полезных нововведений`
  **Пример именования PR-а**: `zharko.yegor/L1`
- Название отчёта: `ЛР№Х_ИО_Фамилия.pdf` (например: `ЛР№1_ЕИ_Жарко.pdf`)
- Перед отправкой PR-а на ревью, необходимо оформить "сквош" коммитов (если коммитов > 1). Ознакомится с инструкцией можно по [данной ссылке](https://htmlacademy.ru/blog/git/how-to-squash-commits-and-why-it-is-needed)
- После выполнения ЛР необходимо убедиться в работоспособности написанного кода.
- Также необходимо убедиться, что работа ведется над актуальной версией проекта. Для этого выполнить `git rebase` текущей ветки на `master` или
  `git merge` ветки `master` в текущую, решив все конфликты, если возникнут.
- Далее выполняется push текущей ветки в удаленный репозиторий и создается PR в ветку `master`.
- Галочку напротив `squash commits` не ставить, т.к. сквош коммитов оформляется самостоятельно
- Назначить `Reviewer` - [yzharko](https://github.com/yzharko) и `Assignee` - себя
- В случае возникновения merge-конфликтов, необходимо их решить.
- Если все в порядке, получаете `Approve` и допускаетесь к очной защите ЛР, после чего выполняется merge в `master`.
